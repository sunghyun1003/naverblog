# 2026-10-17 발행 일정 잠금 해소

## 원인

- 예약 해제 API/버튼 부재. 상태 전이 정의에 역방향 값만 있고 실제 사용 경로가 없었다.
- GitHub 삭제·목록 선택 로직이 scheduled를 실제 발행처럼 보호해 예약 원고를 삭제할 수 없었다.
- 발행 완료 API는 예약 상태만 허용. 화면은 URL을 선택이라고 안내하면서 빈 URL이면 아무 작업 없이 반환했다.
- 전체 일정 건수를 '오늘 예약'으로 표시하고, 실제 알림이 없는데 '예약 알림'이라고 표시했다.
- 공통 상단 알림은 고정 바로가기였으며 미확인 알림처럼 보이는 점이 항상 표시됐다.
- 미사용 초기 샘플 원고/활동 데이터가 소스에 남아 있었다(실제 화면에서는 사용되지 않음).

## 수정

- DELETE /api/contents/:id/schedule: 오래된 미완성 원고도 해제 가능. 원문·이미지·검수 상태·버전 보존, 중복 해제는 무해. 발행·삭제 기록은 되돌리지 않음.
- 기존 예정 시간 변경, 예정 상태 단건·선택 삭제 허용. 삭제 응답도 실제 deleted 상태로 반환.
- 해제 시 DB의 이전 예약 행은 비예약 prepared 상태로 전환. 저장 응답을 화면에 즉시 반영해 DB 지연이 이전 예약으로 화면을 되돌리지 않게 함.
- 기존 두 건처럼 저장소에서 복구한 해제도 백그라운드 동기화가 목록·상세 캐시·DB 예약 행에 함께 반영한다. 일반 페이지 로딩에는 원격 호출을 추가하지 않는다.
- 완성 원고는 예약 없이 수동 발행 완료 기록 가능. URL 선택. 실제 게시했다는 확인창 제공.
- 로컬 모드도 자동 게시 어댑터를 호출하지 않고 기록만 저장.
- 메뉴 '발행 관리', 상태 '발행 예정'. 자동 발행·알림 미구현 명시, 한국 시간 입력/표시.
- 상단을 '운영 바로가기'로 표시하고 가짜 미확인 점 제거. 미사용 샘플 데이터 제거.
- 실제 발행 완료 원고 삭제 보호 유지. 직접 수정·재작성은 예약 해제 후 가능하도록 화면과 서버 제약 일치.
