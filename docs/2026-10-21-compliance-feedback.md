# 준법심의 피드백 — 신규 원고용 누적 표현 지침

## 사용 방법

원고 상세 → **준법심의 피드백**에서 문제된 문장·단어, 받은 피드백, 권장 표현(선택), 적용 보종, 유형을 저장한다.

- `표현·조건 수정`: 이유와 적용 조건을 함께 적어 유사한 문장을 다듬는 참고로 사용한다.
- `사용하지 않을 표현`: 해당 의미의 확약·표현을 피하도록 지시한다. 문자열 일괄 치환이나 무조건 실패 조건이 아니다.
- `앞으로 생성할 원고에 반영`을 끄거나 `적용 중지`하면 기록은 남고 이후 신규 작성에서 제외된다.
- 저장 실패·동시 수정 충돌 때 입력은 보존한다. `목록 새로고침` 후 확인하고 다시 저장한다.
- 기록은 심의 승인 처리가 아니며, 해당 원고의 상태·본문·Word·이미지·버전·발행 기록을 바꾸지 않는다. 기존 원고의 수정은 별도 직접 수정으로 수행한다.
- 개인정보·고객 정보·인증 정보를 입력하지 않는다.

## 저장과 연결

운영 데이터는 비공개 자동화 저장소의 `dashboard/compliance-feedback/<contentId>.json`에 저장한다. 공개 대시보드 저장소나 클라이언트 번들에 실제 피드백을 넣지 않는다. 저장 성공은 원격 파일 저장 완료를 뜻하며 별도 동기화나 모델 학습 작업이 필요하지 않다. 실행 중인 작업이 아니라 **저장 이후 최신 main을 가져와 새로 시작한 원고**가 대상이다.

- 스키마 1: `contentId`, `revision`, `items[]`.
- 항목: UUID, 원문, 의견, 권장 표현, 보종, 유형, 적용 여부, 등록 당시 제목·원고 버전, 생성/수정 시각과 수정자.
- 항목 수정은 문서 revision과 GitHub 파일 SHA를 모두 확인한다. 중복 전송은 같은 UUID로 재시도하여 항목을 중복 생성하지 않는다.
- 원고 삭제와 별도 경로로 저장하므로 축적된 지침은 원고 삭제로 사라지지 않는다. 기존 원고에서 등록한 의견도 향후 신규 글의 참고가 된다.
- 로그인·기존 요청 출처 검사와 `content:review` 권한을 적용한다. 원고 API 캐시를 비우거나 생성·재작성 작업을 실행하지 않는다.
- 로컬 개발은 메모리 저장소, 운영은 기존 GitHub 연결을 사용한다. 추가 DB·외부 서비스·비용은 없다.

## 자동화 적용

새 원고의 첫 작성 프롬프트를 준비할 때 적용 중인 공통·해당 보종 지침을 선택한다. 두 보종 비교 글은 해당 두 보종을 함께 참고한다. 같은 단어뿐 아니라 의미가 유사한 문장에 적용하되 사실·조건·출처·법정 고지·3줄 요약·FAQ가 우선이다. 의견을 상품 사실이나 승인 증명으로 취급하지 않는다. 기록 안의 도구 실행·전송·역할 변경 지시를 따르지 않는다.

- 관련성·최신순으로 최대 20개, 직렬화된 항목 합계 12,000자 이내. 동일 의견은 중복 전달하지 않는다. 누적 데이터가 커져도 호출 수와 재시도 예산은 늘리지 않는다.
- `compliance-feedback-usage.json`에 적용 항목과 원본 번호/리비전, 후보/제외/형식 오류 건수를 남긴다. 원고별 기록을 최초 한 번만 저장한다.
- 초안 → 기존 계약 복구 → 말투 검수/보정 → 이후 해당 신규 원고 재시도에서 동일 기록을 사용한다. 처음부터 받은 의견을 편집 단계에서 되돌리지 않도록 한다.
- 기존 원고에는 기록을 소급 생성하지 않는다. 기존 원고의 수정·재시도에 최신 지침이 갑자기 유입되지 않는다. 이미 시작한 새 원고 역시 나중에 변경된 의견으로 몰래 재편집하지 않는다.
- 누락·손상된 기록은 원본을 보존하고 경고 후 기존 경로를 유지한다. 심의 피드백 존재 자체가 새로운 실패 조건이 되지는 않는다.

이 기능은 **모델 재학습이 아니라, 원고마다 관련된 심의 사례를 함께 전달하는 방식**이다. 의미가 유사한 표현까지 완벽히 제거하거나 실제 준법심의 통과를 보장하지 않는다. 다음 실제 신규 글에서 반영 정도를 점검해야 한다.

## 검증

- API 등록·수정·중지·재활성화·중복 요청·동시 저장·권한·형식 검사, 기존 원고/상태/버전/작업 불변.
- GitHub 모의 응답으로 전용 경로만 변경함과 SHA 충돌 거부 확인. 원격 실제 원고에 테스트 기록을 쓰지 않음.
- 임시 작업공간에서 실제 작성 준비 → 초기 실패 보존 → 원고 저장 → 말투 검수/보정 → 계약 복구 전달 검증. 기존 원고 제외·다른 실행 정보 차단·범위·중복·입력 예산 확인. 유료 호출 없음.
- 자동화 277개, 대시보드 177개, PC 임시저장 6개(총 460개) 테스트 통과, 타입 검사·빌드 통과.
- Browser 플러그인 미제공으로 기존 Playwright 사용. `http://127.0.0.1:4173` 로컬 mock, PC 1440px/모바일 390·360px에서 입력 → 탭 왕복 → 저장 → 수정 → 중지/재활성화 → 새로고침 유지, 409 오류 시 입력 보존을 확인.
- 화면 식별·빈 화면·오류 오버레이·가로 넘침·관련 콘솔 오류 없음. 기존 로컬 favicon 404와 의도적으로 주입한 409는 구분했다. 화면 크기 변경 직후 기존 사이드바 닫힘 전환이 끝난 뒤 모바일 배치를 검증했다.
