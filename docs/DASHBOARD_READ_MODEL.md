# 대시보드 조회 경로 (2026-09-13)

## 유지하는 경계

- GitHub 비공개 저장소: 원고·이미지·검증 자료의 원본, 자동화 실행.
- 기존 Neon: 화면용 목록과 완성된 상세 JSON을 저장하는 조회용 사본.
- Firebase Hosting: 빌드된 화면과 해시가 붙은 정적 파일을 직접 전송.
- Cloud Run: 로그인, `/api/**`, 이미지 접근, 수정·실행 요청.
- 좌측 정렬·페이지 위치·원고 상태·검토 체크 제거 등 기존 화면 정책은 변경하지 않는다.

## 갱신

1. 비공개 저장소의 `Sync dashboard read model`이 자동화 시작·완료 후 실행된다.
2. GitHub가 서명한 단기 신원 토큰으로 `/api/internal/sync`에 요청한다. 서버는 저장소, main 브랜치, 전용 workflow 경로, 발급자·대상·만료·서명을 검증한다. 별도 장기 비밀키가 없다.
3. 서버가 GitHub 파일 SHA를 비교하고 변경된 원고만 최대 5건씩 재조립한다. 이미지 바이트는 이 과정에서 읽지 않는다.
4. 원고 본문, 이미지 manifest, 복구 checkpoint, 검증 결과, 변경 이력을 상세 JSON에 함께 보존한다. 실행 이력은 `output/history/index.json` 한 번으로 읽는다.
5. 일반 탭 이동은 저장된 사본만 읽는다. 누락된 사본은 최초 조회 시 채우고, 명시적 새로고침은 원본을 다시 확인한다.

시간당 보강 동기화가 이벤트 누락을 보완한다. 실패한 동기화는 GitHub Actions에 실패로 남고 기존 정상 자료는 유지한다. 원고 재생성이나 AI 호출을 실행하지 않는다. 백업 주기는 `.github/workflows/sync-dashboard.yml`에서 관리한다.

## 브라우저

사용자 인증 뒤 해당 사용자·브라우저 탭의 sessionStorage 사본을 복원한다. 최근 자료를 즉시 표시한 뒤 재조회한다. 동일 요청을 공유하고, 탭을 떠난 요청 하나의 취소가 다음 탭 요청을 취소하지 않는다. 로그아웃·수정으로 무효화된 과거 응답은 다시 캐시에 쓸 수 없다. API 응답은 공개 CDN에 저장하지 않는다.

## 조회 응답 전송

목록·상세·트렌드·실행 이력·자동 실행 설정의 GET JSON만 2KB 이상일 때 gzip으로 전송한다. 압축을 지원하지 않는 요청은 원래 JSON을 받는다. 비동기 스트림과 압축 수준 4를 사용해 서버 CPU 부담을 제한한다. `Vary: Accept-Encoding`과 `private, no-store`를 유지한다. 로그인·변경 요청·이미지 파일은 제외하며 압축된 요청 본문을 새로 허용하지 않는다.

## 배포·검증

홈은 `/api/trends/summary`에서 수집일·검색어/후보 건수·최상위 제목만 받는다. 전체 트렌드와 같은 저장 자료와 새로고침 경로를 사용한다. 브라우저의 요약 캐시와 전체 검색 캐시는 분리하여 요약 조회로 목록이 잘리지 않게 한다. 메모리 전용 요청 캐시는 sessionStorage 재직렬화를 유발하지 않는다.

- `005_dashboard_snapshots.sql`을 먼저 적용한다. 기존 데이터 테이블을 삭제하거나 바꾸지 않는다.
- 대시보드 `main` push → 테스트 → DB 검증 → Cloud Run → Firebase Hosting 순서로 배포한다.
- 배포 계정에는 기존 Cloud Run 권한 외 Firebase Hosting 배포 권한이 필요하다.
- 2026-09-14 사용자 승인 후 `github-codex-automation` 서비스 계정에 `roles/firebasehosting.admin`을 추가했고 GitHub Actions의 Firebase 정적 배포 성공을 확인했다. 별도 수동 배포를 요구하지 않는다.
- 비공개 저장소 코드를 push한 뒤 `Sync dashboard read model`을 1회 실행하여 기존 자료를 채운다. 출력 `remaining: 0`을 확인한다.
- 후속 자동화 실행 후 동일 workflow 성공 여부로 사본 갱신을 확인한다.
- 회귀 검증: `npm run verify`, 비공개 저장소 `npm test`. 스냅샷 조회 무외부호출, 일괄 저장, 사용자별 캐시, 요청 취소, 삭제 보호, OIDC 거부, 기존 이미지·복구 동작을 포함한다.

서버 최소 인스턴스는 0을 유지한다. 따라서 오랜 미사용 뒤 첫 로그인/첫 API 요청의 서버·DB 기동 지연이나 네트워크 지연까지 0초를 보장하지는 않는다. 유료 상시 실행 서버나 신규 DB는 추가하지 않았다.
