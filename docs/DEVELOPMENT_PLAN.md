# 블로그 자동화 통합 개발 계획

## 1. 제품 목표

팀원이 한 시스템에서 보험·금융 콘텐츠의 소재 수집, 기획, 생성, 검수, 승인, 예약, 발행, 성과 확인을 수행한다.

성공 조건은 다음과 같다.

- 콘텐츠의 현재 상태와 담당자를 누구나 확인할 수 있다.
- 모든 사실 주장에 출처와 기준일이 연결된다.
- 원고의 모든 버전과 수정 주체가 기록된다.
- 광고 위험과 최종 발행 권한을 분리한다.
- Slack, 웹, 자동화 도구가 하나의 API와 데이터베이스를 사용한다.
- 동일 요청이 반복돼도 콘텐츠나 발행이 중복되지 않는다.

## 2. 전체 구성

| 영역 | 책임 |
| --- | --- |
| 웹 관제 페이지 | 기획, 편집, 근거 확인, 승인, 발행, 사용자 관리 |
| Slack 앱 | 요청, 알림, 담당자 호출, 관제 페이지 링크 |
| API 서버 | 권한, 콘텐츠 상태 전환, 모든 업무 규칙 |
| 작업 실행기 | 자료 수집, AI 작성, SEO/GEO, 말투 보정, 검수 |
| PostgreSQL | 콘텐츠, 출처, 주장, 버전, 승인, 발행, 감사 이력 |
| n8n | 예약 실행, 외부 API 연결, 재시도, Slack 알림 |
| 로컬 발행 보조 | 로그인된 브라우저에서 네이버 발행 준비 |

핵심 업무 규칙은 n8n이나 Slack 안에 넣지 않고 API 서버에 둔다.

## 3. 단계별 구축

### 단계 0. 제품 정책과 경계

- 정보형과 광고형 콘텐츠 분류 기준
- 수집 허용 출처 목록
- 인용·원문 보관 정책
- 역할과 승인 권한
- 개인정보와 계정 보안 기준
- 장애 시 수동 운영 절차

완료 조건: 정책 문서와 승인 책임자가 정해진다.

### 단계 1. 관제 프론트엔드

- 앱 셸, 사이드바, 상단 탐색
- 콘텐츠 목록, 검색, 상태 필터
- 콘텐츠 생성 요청
- 원고 검토와 출처 확인
- 버전 차이와 말투 보정 차이
- 승인·반려 흐름
- 반응형과 접근성

완료 조건: 샘플 데이터로 생성 요청부터 승인까지 동작한다.

### 단계 2. 인증·권한·감사 로그

- 회사 계정 로그인
- 역할 기반 권한: 기획자, 편집자, 검수자, 승인자, 발행자, 관리자
- 팀과 사용자 관리
- 콘텐츠별 담당자
- 생성, 수정, 승인, 반려, 발행 이벤트 기록

완료 조건: 권한 없는 사용자는 승인·발행할 수 없고 모든 변경 주체가 남는다.

### 단계 3. 콘텐츠 도메인 API

- 콘텐츠 생성·조회·수정
- 상태 전이 검증
- 버전 생성과 비교
- 댓글과 반려 사유
- 첨부와 출처 연결
- 중복 실행 방지용 요청 키

권장 상태:

`IDEA → RESEARCHING → BRIEF_READY → DRAFTING → REVIEW_READY → APPROVED → SCHEDULED → PUBLISHED → MEASURED`

실패 상태는 본 상태를 덮지 않고 별도 `job_status`로 기록한다.

### 단계 4. 트렌드 수집기

- 네이버 검색 API: 블로그, 카페, 뉴스, 지식iN
- YouTube Data API: 영상 메타데이터와 공개 성과
- 커뮤니티: 공식 API, RSS, 허용 URL
- 중복 제거와 URL 정규화
- 최신성, 관련성, 반복 노출, 출처 신뢰도 점수
- 유사 주제 묶기

완료 조건: 허용 출처에서 수집한 항목이 트렌드 보관함에 중복 없이 들어온다.

### 단계 5. 근거와 기획 엔진

- 인기 콘텐츠에서 질문, 관점, 목차 힌트만 추출
- 정부·감독기관·협회·약관에서 사실 재검증
- 주장 장부 생성
- 타깃 독자, 검색 의도, 핵심 질문, 차별화 관점 생성
- 원문 한 개를 단순 재작성하지 못하게 제한

주장 장부 필수 필드:

- 주장 본문
- 출처 URL과 기관
- 근거 원문 위치
- 기준일과 수집일
- 신뢰 등급
- 검증 상태
- 사용된 원고 버전

### 단계 6. 콘텐츠 생성 파이프라인

1. 기획서 생성
2. 목차 생성
3. 근거 범위 안에서 초안 작성
4. SEO 편집
5. GEO 편집
6. 완성 원고 생성
7. 사람 말투 보정 skill 적용
8. 사실·수치 재검수
9. 광고 위험 검수
10. 사람 승인 대기

각 단계는 새 버전을 만들고 이전 버전을 덮어쓰지 않는다.

### 단계 7. 사람 말투 보정 Skill Runner

입력:

- 완성 원고 버전
- 말투 설정
- 보호할 수치, 상품명, 법령, 인용, 고지
- skill 이름과 버전

출력:

- 보정된 원고
- 변경 전후 차이
- 변경된 중요 주장
- 경고
- 실행한 skill 버전

완료 조건: 보호된 문장이 변경되면 자동으로 검토 실패 처리된다.

### 단계 8. Slack 연동

- 콘텐츠 생성 명령
- 오늘의 트렌드 요약
- 작업 완료와 실패 알림
- 담당자 지정과 검토 요청
- 관제 페이지 딥링크

Slack 메시지에서 최종 발행하지 않는다. 중요한 승인은 원고와 근거를 함께 볼 수 있는 관제 페이지에서 처리한다.

### 단계 9. 네이버 발행 보조

- 승인된 원고만 발행 가능
- 발행자 권한 확인
- 제목, 본문, 이미지, 태그, 카테고리 준비
- 발행 직전 최종 확인
- 네이버 예약 발행 활용
- 발행 URL과 시간 기록
- 중복 발행 방지

초기에는 사람이 최종 발행을 확인하고, 안정화 후 브라우저 입력 보조 범위를 결정한다.

### 단계 10. 성과와 개선

- 게시물 조회수, 방문자, 유입, 재방문, 반응
- 콘텐츠 유형과 성과 연결
- 발행 후 정정 횟수
- 검색 의도별 성과
- 주제 추천 가중치 개선

성과 데이터가 낮다는 이유만으로 금융 사실이나 필수 고지를 줄이지 않는다.

## 4. 핵심 데이터 모델

| 테이블 | 주요 내용 |
| --- | --- |
| users | 회사 사용자와 계정 연결 |
| roles, user_roles | 역할과 권한 |
| contents | 콘텐츠 식별자, 상태, 담당자 |
| content_versions | 원고와 생성 단계별 버전 |
| sources | 수집 원문 메타데이터와 사용 범위 |
| claims | 사실 주장과 출처 연결 |
| jobs | 수집·생성·검수 작업 상태 |
| qa_results | SEO, GEO, 사실, 광고 검사 결과 |
| approvals | 승인·반려와 사유 |
| publications | 예약·발행 결과와 URL |
| audit_logs | 사용자·시스템의 모든 중요 변경 |
| metrics | 발행 이후 성과 |

## 6. 품질 보증

- 단위 테스트: 상태 전이, 권한, 중복 방지, 점수 계산
- 통합 테스트: 수집→기획→생성→검수→승인
- 기준 원고 테스트: 사람이 승인한 글로 말투와 품질 회귀 확인
- 한국어 자연스러움 회귀 테스트: 번역체·추상 표현 30~50개를 bad→good fixture로 고정하고 HIGH/MEDIUM 기준을 검증
- 시각 테스트: 데스크톱·태블릿·모바일
- 접근성: 키보드, 포커스, 명도 대비, 색상 외 상태 표현
- 장애 테스트: API 제한, 모델 오류, 네트워크 중단, 중복 요청

## 7. 현재 구현 범위와 다음 순서

| 영역 | 현재 상태 | 연동 후 남는 일 |
| --- | --- | --- |
| 단계 0 정책 | 입력 템플릿 준비 | 회사 책임자와 실제 값 확정 |
| 단계 1 관제 화면 | API 연결 포함 구현·브라우저 검증 | 회사 계정 사용자 표시 |
| 단계 2 권한·감사 | 역할 규칙·차단·감사 이벤트 구현 | 회사 SSO와 내부 사용자 UUID 매핑 |
| 단계 3 도메인 API | 생성·조회·파이프라인·승인·반려·예약·발행 구현 | 운영 인증 미들웨어 적용 |
| 단계 4 수집기 | 계약과 결정론적 모의 수집기 구현 | 네이버·YouTube·허용 커뮤니티 연결 |
| 단계 5 근거·기획 | 출처·주장 장부·기획 생성 흐름 구현 | 공식 자료 검색 제공자 연결 |
| 단계 6 생성 | 9단계 실행·버전·실패 이력·중복 방지 구현 | 실제 AI 모델 연결 및 비용 한도 설정 |
| 단계 7 말투 Skill | 보호 문구 검사 계약·모의 구현·실패 테스트 | 보유 skill 실행 방식 연결 |
| 단계 8 Slack | 알림 어댑터 계약·모의 구현 | Slack 앱과 채널 연결 |
| 단계 9 발행 | 승인·예약·발행 게이트와 모의 발행 구현 | 네이버 발행 보조 방식 확정·연결 |
| 단계 10 성과 | 데이터 스키마 준비 | 네이버 통계 수집 방식 연결 |

외부 연동 전 자율 구현 범위는 완료됐다. 다음 순서는 [연동 체크리스트](./INTEGRATION_CHECKLIST.md)의 회사 로그인과 운영 데이터베이스를 먼저 확정한 뒤, 각 모의 어댑터를 실제 제공자로 하나씩 교체하는 것이다.
