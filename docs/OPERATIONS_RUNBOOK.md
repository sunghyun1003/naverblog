# 운영 실행·장애 대응

## 로컬 실행

터미널 1:

```bash
npm run dev:api
```

터미널 2:

```bash
npm run dev:web
```

웹: `http://127.0.0.1:4173`  
API: `http://127.0.0.1:8787`

기본 저장소는 서버 재시작 시 초기화되는 인메모리 모드다. PostgreSQL 전환 전에는 `server/db/README.md`의 선행 조건을 확인한다.

## 전체 검증

```bash
npm run verify
```

이 명령은 프론트·서버 타입 검사, 단위·통합 테스트, 프론트·서버 빌드를 순서대로 실행한다.

GitHub의 push와 pull request에서도 `.github/workflows/ci.yml`이 같은 명령을 실행한다.

## 장애 확인 순서

1. `/health` 응답 확인
2. 콘텐츠 상세의 최신 `jobs`와 실패 단계 확인
3. 실패 직전 `content_versions` 확인
4. 외부 제공자 상태·쿼터 확인
5. 같은 멱등성 키를 재사용할지 새 실행으로 만들지 결정

한국어 자연스러움 검사가 실패하면 원고 패키지의 `native-korean-quality.json`에서 문제 문장과 권장 표현을 확인한다. HIGH 1건 또는 MEDIUM 3건 이상이면 사람 검토 상태로 남으며, 자동 재작성 후에도 같은 기준을 통과해야 승인할 수 있다.

같은 멱등성 키는 기존 작업을 반환한다. 문제를 수정하고 새 작업을 실행할 때는 새 키를 사용한다.

## 원고 직접 수정·삭제

- 원고 상세 화면의 **직접 수정**에서 제목과 본문을 저장하면 `manual` 새 버전이 만들어지고 검토 대기 상태로 돌아간다. 기존 자동 생성 버전과 출처·변경 이력은 보존된다.
- 수동 수정 후에는 최종 승인 확인과 보험료·보장 범위·특약 등 핵심 용어를 다시 확인한다. 화면의 한국어 자연스러움 결과는 재검수 필요 경고로 표시된다.
- **삭제**는 소프트 삭제다. GitHub 원문과 Neon 이력은 지워지지 않고 콘텐츠 목록에서만 숨겨진다. 예약·발행된 원고는 삭제할 수 없다.

## 복구 원칙

- 실패한 자동화가 이전 원고 버전을 삭제하지 않는다.
- 승인되지 않은 원고는 예약·발행하지 않는다.
- 발행 결과가 불명확하면 자동 재발행하지 않고 외부 URL을 먼저 확인한다.
- 데이터베이스 장애 시 화면을 읽기 전용으로 전환한다.
- 보안·광고 위험 검사가 실패하면 사람이 해제할 수 없고 새 버전으로 재검수한다.
