# 자동화 시스템 검증 기록

## 자동 검사

- `npm run check`: 통과
- `npm test`: 12개 통과, 실패 0개
- `npm run build`: 통과
- 빌드된 API 기동 및 `/health`: `ok`, `memory`, `mock` 확인
- 브라우저 콘솔 경고·오류: 0건

검증 범위:

- 콘텐츠 상태 전이 허용·차단
- 역할별 실행·승인 권한
- 콘텐츠 생성과 파이프라인 멱등성
- 수집→근거→기획→초안→SEO→GEO→말투→QA→알림 9단계
- 보호 문구 변경 시 작업 실패와 이전 버전 보존
- 승인 체크, 예약, 발행 상태 전이
- HTTP API 생성부터 검수 상세 조회
- PostgreSQL 핵심 테이블·고유 제약 마이그레이션 정적 검사

## 브라우저 기능 검사

- API 연결 배너: 로컬 자동화 파이프라인 연결 상태 표시
- 콘텐츠 생성 모달: API에 생성 요청 후 실제 9단계 파이프라인 실행
- 제목 검색: 입력한 제목에 맞는 행만 표시
- 상태 필터: `검토 필요` 선택 상태와 대상 행 표시
- 검수 화면 이동: 생성한 제목·원고·근거·5개 버전·9개 작업 단계 표시
- 승인 조건: 출처와 광고 표현 확인 전에는 승인 불가
- 승인 완료: 두 항목 확인 후 상태가 `승인 완료`로 변경되고 예약 건수와 분리
- 1280px 화면: 문서 전체 가로 넘침 없음

확인 화면: [대시보드 구현 캡처](./design/automation-dashboard-implementation.png)

## 시안 비교

1. 좌측 탐색, 중앙 작업 영역, 우측 보조 패널의 3단 구조를 유지했다.
2. 주황색은 주요 실행 버튼과 선택 상태에만 사용했다.
3. 카드 그림자 대신 보조 배경과 1px 구분선으로 계층을 표현했다.
4. 대시보드는 상태 요약, 필터, 목록, 오늘 할 일 순서를 유지했다.
5. 검수 화면은 문서 목차, 원고, 검수 결과와 출처를 한 화면에서 비교하도록 유지했다.

대시보드 상단 문구는 시안과 동일하다. 검수 원고의 단정적인 보험 표현은 실제 발행 오인을 막기 위해 약관 확인과 개인별 유불리 안내 문구로 바꿨다. 검토 콘셉트에 생성된 당근형 심볼은 브랜드 오인 방지를 위해 중립적인 자체 문서 마크로 교체했다.

## 연동 후 검증할 항목

- 실제 PostgreSQL에 마이그레이션·계약 테스트 실행
- 회사 SSO 사용자와 역할 매핑 검증
- 네이버·YouTube 쿼터, 재시도, 차단 응답 검증
- 보유 사람 말투 skill의 보호 문구·타임아웃 검증
- Slack 서명과 알림 딥링크 검증
- 네이버 발행 보조의 세션 만료·중복 발행 검증
- 모바일 실기기 시각·키보드 접근성 검사

현재 내장 브라우저에서는 실제 렌더링 크기가 1280×720으로 고정돼 모바일 실기기 검사를 대체할 수 없었다. 767px 이하 레이아웃 규칙과 모바일 메뉴 DOM은 코드 수준에서 포함돼 있다.
