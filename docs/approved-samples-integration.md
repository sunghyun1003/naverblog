# 회사 승인 블로그 원고를 생성 기준으로 연결

적용일: 2026-10-06. 원본 `samples/*.docx`는 수정하지 않습니다.

## 확인한 원인과 자료

- 제공된 원고는 72개입니다. 자동차보험 65개, 여행자·운전자·화재·일상생활배상책임·펫·홀인원·일반 보험 각 1개입니다. 71개에 상단 핵심포인트가 있습니다.
- Word 파일 본문이 일반 문단이 아니라 HTML을 넣은 `altChunk/MHT`여서 일반 DOCX 문단 추출로는 빈 결과가 나왔습니다. Python 표준 라이브러리로 HTML 본문·표·링크·FAQ 답변까지 추출합니다. 웹 목차·조회수·배너·스크립트는 제외합니다.
- 기존 생성기는 오래된 문체 가이드의 4줄만, 편집기는 6줄만 전달했습니다. 실제 72개 원고는 사용하지 않았습니다.
- 본문의 `합니다체`를 어미만으로 수정하도록 하는 기존 검사와 샘플 문체가 충돌했습니다. 자연스러운 정중체는 보존하도록 수정했습니다.
- 공식 근거 조사 허용 목록에 자사 사이트가 없었습니다. [캐롯](https://www.carrotins.com/)과 [한화손보](https://www.hwgeneralins.com/)를 자사 상품 근거용으로 추가합니다. 두 사이트는 **하나의 기관**으로 계산하며 외부 독립 교차검증 두 곳으로 세지 않습니다.

## 앞으로의 처리

1. 예약·수동 생성, 수정 요청, 실패 단계 재개 시 → GitHub `naverblog/main`의 최신 `samples`를 한 번 읽어 추출합니다.
2. 보종·질문과 관련된 원고 검색 → 생성·조사에는 최대 2개, 수정·검수에는 최대 1개를 전달합니다. 같은 제목의 복제본은 중복 선택하지 않습니다.
3. 공통 편집 기준 + 실제 제목·핵심포인트·소제목·도입·설명 문단·FAQ → 각 단계에서 같은 기준을 사용합니다. 샘플 전체를 매 호출에 넣지 않습니다. 추가 AI 호출이나 별도 유료 검색 DB는 없습니다.
4. 생성 단계의 샘플 입력은 최대 6,500자, 조사 4,200자, 편집·검수 3,900자입니다. **토큰 수가 아닌 문자 상한**이며 샘플 도입 전보다 이 범위의 입력이 추가됩니다.
5. 새 원고에는 실제 사용한 파일명·내용 해시·라이브러리 버전·단계별 선택을 `approved-sample-usage.json`으로 남깁니다. 어느 샘플이 적용됐는지 사후 확인할 수 있습니다.

최신 파일 읽기에 실패하면 경고를 남기고 자동화 저장소의 72개 승인 샘플 저장본으로 계속합니다. 샘플 서버 문제 때문에 본문까지 실패시키지 않습니다. 이후 `samples`에 DOCX를 추가하면 다음 작업에서 반영됩니다. 다른 형식 파일은 현재 자동 수집 대상이 아닙니다.

## 핵심포인트와 브랜드 USP

별도 광고 박스를 하나 더 만들지 않고, 기존 상단 **3줄 요약**을 승인 샘플의 핵심포인트 역할로 사용합니다. 기존 본문·복사·HTML·네이버 도우미가 같은 필드를 사용하므로 전달 과정에서도 유지됩니다.

- 두 항목: 해당 글에서 독자가 구분해야 할 핵심 답변.
- 한 항목: 주제에 맞는 **자사 상품명 + 특징 + 적용 조건**. 자동차보험 상품은 **한화손보 캐롯 자동차보험**으로 표기합니다. 기존 공식 조사 단계에서 확인된 주장·근거 ID와 연결.
- 현재 USP 근거가 없으면 상품 장점을 지어내지 않고 브랜드의 편집 소개와 확인된 독자 확인사항으로 대체. 이 이유만으로 원고 재생성이나 실패를 추가하지 않습니다.
- 대응 샘플이 없는 암·실손·건강 등은 공통 설명법을 사용합니다. 다른 보종의 상품 혜택을 가져오지 않습니다.

원본은 회사 승인 자료로 활용하지만 과거 할인 수치·약관 조건·심의번호를 새 원고의 현행 근거로 간주하지 않습니다. 원고가 샘플에 기반했다는 사실만으로 새 심의를 받은 것이 아닙니다. AI의 USP 동반 인용을 보장하지도 않습니다.

## 2026-10-07 명칭·이미지 다양성 보완

- 회사 지정 표기: 사명은 **한화손보**, 자사 자동차보험 상품명은 매번 **한화손보 캐롯 자동차보험**. 일반 보종명 ‘자동차보험’이나 타사 상품은 확장하지 않습니다. 운전자·여행자 등 다른 보종에 캐롯을 강제로 붙이지 않습니다.
- 조사·생성·수정·복구·말투 검수의 공통 프롬프트와 승인 샘플 발췌본에 같은 규칙을 전달합니다. 원본 DOCX와 원문 저장본은 변경하지 않습니다.
- 출처 연결과 최종 저장 시 명확한 회사/상품명 변형을 코드로 보정합니다. 본문·3줄 요약·FAQ·SEO·GEO·이미지 대체문구에 적용하고 출처 원문 제목·URL·근거 ID·수치·조건은 보존합니다. 옛 기관명과 새 기관명은 근거 검사에서 같은 기관으로 계산해 기존 산출물 재개와 호환합니다.
- 이미지 선택은 기존 행동/은유 이력에 더해 배경·인물 여부·카메라 구도의 최근 반복을 낮추는 방식입니다. 자동차 생활 장면은 6개에서 12개, 여행 장면은 6개에서 9개로 확장합니다. 손·세부 사물에는 원경이 아닌 근접 구도를 적용합니다. 다른 보종도 공통 선택 개선을 사용합니다.
- 다양성은 선택 우선순위이지 새 검수 실패 조건이 아닙니다. 장면 풀이 소진되면 기존 주제 안전 장면을 재활용합니다. 이미지 3장, 기존 모델·API 호출·재시도 횟수·품질 기준·AI 이미지 주석을 유지합니다. 새 장면의 실제 생성 품질은 오프라인 검사만으로 보장하지 않습니다.
- 기존 원고 일괄 덮어쓰기나 유료 재생성은 하지 않습니다. 다음 생성·수정·재렌더링부터 새 표기 규칙이 적용됩니다.

## 회귀 방지

3줄 요약·FAQ, 자연스러운 SEO 키워드 배치, 자극적이지 않은 제목 다양성, AI 이미지 주석, 기존 이미지 생성·재시도·산출물 보존·자동 발행 금지를 유지합니다. 과거 샘플에 있는 과장 제목이나 가입 재촉은 따라 하지 않습니다. 새 스키마 필드나 화면 필수 입력을 추가하지 않았고 기존 원고를 일괄 변경하지 않습니다.

검증: DOCX 추출 검사, 실제 72개 저장본 검사, 보종 분리·중복 제외·입력 길이·장애 시 저장본 사용, 6개 프롬프트 경로 통합, 기존 전체 파이프라인 회귀 검사. 실제 유료 원고 재생성이나 네이버 발행은 이 변경의 오프라인 검사에 포함하지 않습니다.

개발 확인 명령:

```powershell
python scripts/test_approved_samples.py
python scripts/build-approved-samples.py --output tmp/approved-samples.json
```

자동화 저장본을 갱신할 때만 출력 경로를 `automation-private/config/approved-samples.json`으로 지정해 검증 후 커밋합니다.
