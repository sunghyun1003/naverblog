# 2026-09-09 자동 생성 반복 실패 분석

## 확인된 원인

9월 4일 복구 테스트 추가 후 `npm test`에서 실행한 준비 스크립트가 실제 GitHub Actions의
`GITHUB_ENV`를 상속했다. 테스트가 임시 복구 폴더, 가짜 원고 번호 `555555`, 테스트 주제
`다이렉트자동차보험`, 근거 조사 생략 플래그를 다음 운영 단계에 넘겼다.

이후 실제 모델은 초안과 말투 검수까지 진행했지만 결과가 `/tmp/evidence-validation-recovery-…`
아래에 저장됐다. 완료 판정은 저장소의 다른 `run-555555`를 읽었고, 결과 커밋/대시보드는
진짜 GitHub 실행 번호로 찾으므로 초안조차 없는 것처럼 보였다.

근거: 실행 34083798811, 34169390575의 `article-generation`, `tone-final-validation`,
임시 경로의 `TONE_REVIEW_COMPLETE`, `Only a quality-checked content package can be recorded` 로그.
OAuth 인증 자체가 이 반복 오류의 원인은 아니다.

## 수정 범위

1. 테스트에 OS 실행 환경만 전달. 실제 인증·GITHUB_ENV·원고 번호·저장 위치는 상속하지 않음.
2. 복구/수정 준비값은 해당 셸의 env 파일로만 전달. 이후 Actions 단계에 전파하지 않음.
3. 모델 호출 전과 패키지 저장 전에 실행 번호/저장 위치 교차 검증.
4. 중복 후크 제거 지시와 최소 1개 후크 강제 규칙의 충돌 제거. 출처·사실·광고 안전 기준 유지.
5. 말투 수정이 구조를 망가뜨린 경우 마지막 유효 원고 유지. 모델 PASS와 실제 구조 검사를 함께 확인.
6. 실패 로그·원고·근거·검수·사용량을 추적 가능한 원고 번호로 보존. 숨겨지는 .log 대신 .txt 저장.
7. 이미 작성된 원고는 근거 조사/초안 재생성이 아닌 말투 검수부터 재개할 수 있음.
8. 대시보드 DB 미러에서도 복구 정보가 유지되도록 기존 버전 metadata에 저장. 화면 레이아웃 변경 없음.

## 복구 원칙

실패 실행의 Actions 백업을 원래 실행 번호로 복구한다. 원래 실패 이력/토큰 기록은 보존하고,
모델의 최종 피드백 파일이 백업에 없던 원고는 임의로 검수 통과 처리하지 않는다.
사용자가 삭제한 원고는 복원하지 않는다. 테스트 번호로 묶인 데이터는 별도 사고 기록으로 보관한다.

## API 전환

자동화 저장소 `docs/openai-api-transition.md` 참고. 키 입력 전에는 기존 OAuth 유지.
실제 API 과금 검증은 키 등록 이후 필요하며, 이번 인증/이미지 API 테스트는 모의 응답으로 진행했다.
