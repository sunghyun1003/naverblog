# Windows PC 네이버 임시저장 도우미 (1차)

대상: `https://blog.naver.com/cest_la_mode`, 카테고리 기본값.

## 범위와 확인 기준

- PC 도우미를 실행한 동안에만 대시보드의 **네이버 임시저장** 버튼이 작업을 보냅니다.
- 기존 생성·검수·발행완료 표시와 독립적입니다. 새 원고나 이미지를 만들지 않고 AI 비용도 추가하지 않습니다.
- 최신 저장 버전, 수동 수정 본문, 현재 본문에 적용된 이미지의 순서를 사용합니다. 3줄 요약·FAQ·출처·안내 문구를 제거하지 않습니다.
- 이미지 파일은 원본과 SHA-256 체크섬(파일 지문)을 비교한 뒤 네이버에 업로드합니다. 외부 이미지 주소만 붙이지 않습니다.
- 자동 발행은 없습니다. 발행 버튼을 선택하거나 공개/예약 설정을 조작하지 않습니다.
- **임시저장 목록에서 글을 다시 열어 제목·본문 전체·이미지 파일과 삽입 순서를 대조한 뒤 완료로 표시합니다.** 저장 버튼 클릭만으로 성공 처리하지 않습니다. 재열기 검증이 불확실하면 사용자의 확인을 요청합니다.
- 글의 내용과 순서는 보존하지만, 네이버 편집기의 서식 변환 때문에 웹 대시보드와 폰트·여백·표가 완전히 같다고 보장하지 않습니다. 첫 원고를 확인한 뒤 별도 스타일 기준을 정합니다.

## 처음 한 번 설정

프로젝트 폴더의 PowerShell에서:

```powershell
npm run writer:setup
```

1. 완성 원고 → **네이버 임시저장** → 블로그 주소 확인 → **PC 연결 코드 만들기**.
2. `npm run writer:pair` → 1회용 코드를 PowerShell 입력란에 붙여넣기.
3. `npm run writer:login` → 열린 전용 Chrome에서 직접 로그인. 다음 실행에도 로그인하려면 네이버의 ‘로그인 상태 유지’를 직접 선택합니다. 추가 인증은 직접 처리합니다.
4. 글쓰기 화면 진입 후 PowerShell에서 Enter.
5. `npm run writer:start` → 이 창을 켜둔 상태에서 대시보드 버튼을 누릅니다.

Chrome과 Node.js 22 이상이 필요합니다. 자동 시작/Windows 서비스 등록은 하지 않습니다.
PC를 재부팅하면 다시 `npm run writer:start`를 실행합니다. 로그인 만료 시 `writer:login`을 다시 진행합니다.

## 저장 확인과 중단

작업을 시작하면 전송 원본 미리보기와 네이버 편집기가 열립니다. 진행 중에는 자동화 창이나 클립보드를 직접 조작하지 마세요. 본문 서식 붙여넣기에 클립보드를 사용하므로 클립보드 내용이 바뀝니다.

- 네이버 임시저장 목록에서 글을 다시 열어 **제목·본문 전체·이미지 수/위치**를 확인합니다.
- 재열기 검증까지 통과하면 대시보드에 **임시저장 확인됨**으로 표시됩니다. 글을 직접 확인하고 발행 여부를 결정하세요.
- ‘확인 필요’로 중단됐지만 저장된 글이 정상이라면 **저장된 것을 확인했어요**. 이는 네이버 공개 발행이나 기존 발행완료 상태를 바꾸지 않습니다.
- 없다면 열린 편집기와 임시저장 목록을 먼저 확인하고 **저장 안 됨 · 다시 보낼 수 있게**. 이미 저장됐다면 이 버튼으로 재전송하지 마세요.
- PC 중단/인터넷 끊김/버튼 불명확/보안 안내는 ‘확인 필요’로 멈춥니다. 자동 재시도하지 않습니다.
- 기존 작성 중 복구 입력을 자동 삭제하거나 이어 쓰지 않습니다. 같은 제목의 임시저장 글이 여러 개여도 임의로 선택하지 않습니다.
- 다음 원고를 보내기 전에는 이전 전송에서 열어 둔 네이버 편집기 탭을 확인 후 닫습니다. 사용자가 수정 중인 글을 자동으로 닫거나 덮어쓰지 않습니다.
- 대기 작업은 90초 동안 PC가 받지 않으면 취소됩니다. 다음 부팅 때 잊고 있던 글을 자동 입력하지 않습니다.
- 원고 내용이 변경되지 않았다면 반복 클릭해도 새 글을 만들지 않습니다.
- 종료: PowerShell `Ctrl+C`. 전용 브라우저도 닫히므로 열린 편집기 내용을 먼저 확인하세요.

## 저장 위치와 보안

`%LOCALAPPDATA%\CarrotBlogWriter` (OneDrive·프로젝트·Git 밖)

- `naver-profile`: 전용 Chrome 프로필. 평소 Chrome 프로필과 분리.
- `device.dpapi`: PC 연결 토큰. Windows 사용자 계정 암호화(DPAPI)로 보관.
- `jobs\작업ID`: 내려받은 원고·이미지·`preview.html`·결과. 오류가 나도 보존.
- NAVER 비밀번호·쿠키·프로필은 서버나 GitHub에 업로드하지 않습니다. 디버깅 시에도 이 폴더를 통째로 공유하지 마세요.
- 서버는 PC 토큰의 해시만 보관하며, PC는 자신의 작업과 그 작업의 이미지 외에 대시보드 API에 접근할 수 없습니다.
- PC 연결 해제는 대시보드 버튼의 연결 화면에서 수행합니다. 이미 네이버에 쓴 글은 삭제하지 않습니다.
- PC 도우미 실행 중에는 15초마다 소량의 상태 요청이 있습니다. 기존 Cloud Run/DB 무료 한도 계산에 포함되므로 사용하지 않을 때 종료할 수 있습니다.

로그인 자동 우회·캡차 해제·IP 우회는 구현하지 않습니다. NAVER가 자동화 접근을 제한하면 중단하며, 계정 소유자가 정책과 이용 가능 여부를 확인해야 합니다.

## 개발 검증

```powershell
npm run verify
npm run writer:setup
npm run writer:test
```

실제 NAVER 동작은 로그인 후 별도 검증해야 합니다. 로컬 모의 편집기 테스트는 네이버의 실제 저장 여부를 증명하지 않습니다.
